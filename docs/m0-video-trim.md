# M0 视频截取

## 源码与范围

原 smoke 固定的上游 `ccda172efba25cbee990a785bba715b90cc42b95` 是 Next/Go 版本；其音频截取代码不属于当前静态前端。当前分支的 `CanvasNodeDefinition`、`CanvasNodeContext.getUpstream/applyOps` 和本地媒体存储已支持独立处理节点，因此本次直接沿用这些接口。

新增的 `builtin:video-trim` 在画布创建菜单中显示为「视频截取」。创建一个该节点，将已有视频节点的输出连到它左侧；预览成功后填写开始和结束秒数，点「导出片段」。结果是右侧独立的视频节点，原文件不变。结果支持现有的播放、下载、本地保存及画布引用。

## 实现

- 仅处理一个有效视频输入；开始和结束必须是有限秒数，范围满足 `0 ≤ 开始 < 结束 ≤ 视频时长`。
- 使用固定版本 `@ffmpeg/ffmpeg 0.12.15` 与单线程 `@ffmpeg/core 0.12.10`，按需加载同站点的 worker、JS 和 WASM；无需模型 API Key、外部处理服务或额外的跨源隔离响应头。引擎原始文件约 32 MB，首次导出会加载它。
- 本地解码、重新编码为 MP4/H.264 和可选的第一条 AAC 音轨，不做关键帧直接复制。精度受源视频帧率和音频采样边界影响，不承诺任意秒数的逐帧精确切点。为兼容 H.264，奇数宽高会补至相邻偶数，最多补一行或一列。
- 导出 Blob 通过已有 `uploadMediaFile` 保存到 IndexedDB，再以现有画布指令创建普通视频节点和连线。失效任务的临时结果会清理。
- 取消会终止读取或 worker；删除节点、替换输入、离开画布或节点因视口裁剪而卸载也会取消。失败不覆盖原视频，可重试。

## 验证

`cd web && bun test` 包含无效范围、零起点和小数区间用例。`bun run build` 验证 worker 和本地引擎资产打包。工作流会构建当前提交并检查首页和引用的 JS，而不再测试另一份旧源码。

浏览器验收使用四秒带音轨样本，将 `1.25–2.75` 秒导出为独立 MP4；检查 1.500 秒 H.264 视频和 AAC 音轨、原节点不变、两条连线和 IndexedDB 输出。还需检查首次打开、无输入、多输入、无音轨、取消、刷新恢复、失败重试以及浅深色主题。

## 后续边界

本次只截取时长，不含画面区域裁切、合并、多轨时间线、批处理或后台任务队列。浏览器会把输入及输出放入内存，大文件受设备内存影响；没有新增静默的文件大小、时长或超时限制。远端视频必须允许读取，受 CORS 限制时应先导入本地文件。Safari、移动设备、长视频及各种第三方编码格式尚未全面验收。

类型检查目前受未修改的 `web/src/components/layout/model-script-editor.tsx:58` 中 Ant Design `styles.content` 的 TS2353 错误阻塞；在修改前的 `fef80d2` 上可复现同一错误。
